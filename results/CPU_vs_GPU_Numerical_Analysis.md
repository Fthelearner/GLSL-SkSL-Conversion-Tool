# CPU vs GPU 渲染差异数值分析

## 差异根源：`sin(x)` 的参数约简（Argument Reduction）

计算 `sin(170.5)` 时，需要先把参数约简到 `[-π, π]` 范围：

```
CPU (libm glibc):  170.5 - 27 × π_cpu  → 余数精确到 64+ 位
GPU (GLSL spec):   170.5 - 27 × π_gpu  → 余数在 fp32 下截断
```

π 在两个实现中的差异（fp32 下约 2.4e-8），乘以 27 倍频次后，约简余数差 ~6.5e-7，导致 `sin()` 输出差 ~6.5e-7。

### sin(x) 在不同实现下的对比

| x | CPU (libm) | GPU (fp32 π约简) | 差异 | 8-bit 色差 |
|---|-----------|-----------------|------|-----------|
| 1.00 | 0.8414709848 | 0.8414682746 | 2.71e-06 | 0.0007 级 |
| 10.00 | -0.5440211109 | -0.5440208912 | 2.20e-07 | 0.0001 级 |
| 31×0.29=8.99 | 0.4212090303 | 0.4212094843 | 4.54e-07 | 0.0001 级 |
| 170.50 | 0.7539121565 | 0.7539083958 | 3.76e-06 | 0.0010 级 |
| 500.00 | -0.4677718053 | -0.4677595198 | 1.20e-05 | 0.0031 级 |

> 注：GPU 值通过 fp32 π 参数约简 + minimax 多项式逼近模拟，实际硬件实现可能略有不同。

### 其他关键函数的差异量级

| 函数 | CPU (fp64) vs GPU (fp32) 典型差异 |
|------|----------------------------------|
| `smoothstep` | ~1e-8（纯代数运算，仅 fp32 截断误差） |
| `fract` | ~1e-7（依赖于 sin 的 hash 函数会放大） |
| `cos` | 同 sin（本质是 sin(x+π/2)） |
| `pow` | ~1e-6（指数运算的 fp32 逼近误差） |
| `normalize` | ~1e-7（rsqrt 的 fp32 逼近误差） |

## 三条放大路径

### 路径 1：有限差分 ×500（water_ripple — 1.07% 像素差异）

**计算链路**：

```
fragCoord = (640.5, 504.5)   // 像素坐标
    │
    ▼
propagatedDistance = distance(uvHomogeneous, waveCenter)
    │  = 0.0010 (接近波纹中心)
    ▼
distanceToWave = propagatedDistance - 2.0 × timeValue
    │  = -0.4890
    ▼
calcWave(d) = -sin(WAVE_FREQUENCY × d) × waveForm(d)
    │  WAVE_FREQUENCY = 31.0
    │  waveForm = smoothstep(-0.6,-0.3,d) × smoothstep(0,-0.3,d)
    │
    │  calcWave(-0.4890):  CPU=0.1506925348  GPU=0.1506923891  diff=1.46e-07
    │  calcWave(-0.4910):  CPU=0.1719135256  GPU=0.1719134496  diff=7.60e-08
    ▼
有限差分梯度 = (calcWave(d+0.001) - calcWave(d-0.001)) / 0.002
    │  放大因子 = 1/(2×0.001) = 500
    │
    │  梯度 CPU = 10.6104954
    │  梯度 GPU = 10.6105302
    │  差异 = 3.5e-5  (sin 差异被放大了 500 倍)
    ▼
intensity = 梯度 × amplitudeDecay × amplitudeSuppress × 0.012
    │  = 3.5e-5 × 0.996 × 0.0022 × 0.012 ≈ 9.2e-10 (此像素衰减严重)
    │
    │  但在 propagDistance=0.3, amplitudeSuppress=0.67 处:
    │  intensity 差异 = 3.5e-5 × 0.24 × 0.67 × 0.012 = 6.7e-8
    ▼
distortedCoord = (uv - 0.15 × normal.xy) × iResolution
    │  纹理采样坐标偏移 ≈ 6.7e-8 × 0.15 × 1280 ≈ 1.3e-5 像素 (此像素)
    │
    │  在波纹强度较大的像素 (propagDist=0.1, intensity≈0.06):
    │  偏移 = 3.5e-5 × 0.66 × 0.23 × 0.012 × 0.15 × 1280 ≈ 0.012 像素
    │
    ▼
双线性插值权重变化 → 纹理采样 RGB 差可达 100+ 级 (maxΔ=101)
```

**关键点**：有限差分公式 `(f(x+δ)-f(x-δ))/(2δ)` 对 δ=0.001 有 500 倍放大。即使 sin 差异仅 1e-7，梯度差异也达 5e-5。在 intensity 较大的像素（接近波纹中心），这转化为 0.01~0.1 像素的纹理坐标偏移。

### 路径 2：迭代累积 ×64 步（purple_cloud — 70% 像素差异）

**hash 函数是致命放大点**：

```
hash(n) = fract(sin(n) × 43758.5453)
```

| n | CPU hash | GPU hash | 差异 |
|---|---------|---------|------|
| 0.0 | 0.0000000000 | 0.0000000000 | 0.00 |
| 1.0 | 0.5462073520 | 0.4276123061 | **0.1186** |
| 57.0 | 0.9352007754 | 0.8730982437 | **0.0621** |
| 113.0 | 0.4611686317 | 0.3241108756 | **0.1371** |
| 170.0 | 0.8759015871 | 0.6821344616 | **0.1938** |
| 171.0 | 0.1957344748 | 0.3362481573 | **0.1405** |

sin(n) 的 ~1e-7 差异乘以 43758 后被放大到 0.004，fract 将差异随机化到 [0, 1] 范围，hash 输出直接偏差 6%~20%。

**raymarching 64 步累积**：

```
射线: ro=(20, 0, 0), rd=(-0.995, 0.100, 0), zstep=0.625, 64 步

步 0  (距离 20.0):  CPU noise=0.1843  GPU noise=0.1769  → density 均 < 0 (未入云)
步 16 (距离 10.1):  CPU noise=0.3614  GPU noise=0.8348  → CPU density<0, GPU density=0.326
    │
    │  GPU 路径已进入云层, CPU 尚未. 从此分叉.
    ▼
    GPU T 开始快速下降: T_gpu *= (1 - 0.326/64 × 100) ≈ T × 0.491
    而 CPU T 不变.
    
步 32: CPU T ≈ 0.97  GPU T ≈ 0.012  → 差异 80 倍
步 48: CPU T ≈ 0.003  GPU T ≈ 0.000  → 光线几乎完全衰减

最终颜色:
    CPU color = 0.3252  → 8-bit ≈ 83
    GPU color = 0.3526  → 8-bit ≈ 90
    差异 = 7/255 (此模拟偏低, 实测达 99/255 即 maxΔ=99)
```

**为什么 70% 像素受影响**：不同屏幕位置的射线以不同角度穿过云层，每处的 noise/fbm 值不同，hash 差异导致"入云"和"出云"的判断在 CPU/GPU 之间完全不同的像素约占总画面的 70%。

### 路径 3：平滑函数的 fp32 截断（linear_gradient_blend — 3.33% 像素差异）

```
smoothstep 的 fp32 计算:

projected = 0.45, edge0 = -0.2, edge1 = 1.2

CPU (fp64):
    t = (0.45 - (-0.2)) / (1.2 - (-0.2))
      = 0.65 / 1.4
      = 0.4642857142857143
    gradient = t²(3-2t) = 0.446519679300

GPU (fp32):
    先用 fp32 计算除法和减法:
    (0.45_fp32 - (-0.2_fp32)) = 0.65_fp32
    (1.2_fp32 - (-0.2_fp32)) = 1.4_fp32
    t_fp32 = 0.65_fp32 / 1.4_fp32 = 0.4642857015132904
    gradient = 0.446519660239

差异: 1.9e-8 (可忽略不计)
```

**linear_gradient_blend 的 3.33% 差异不来自 smoothstep**，而是来自预乘 alpha 的纹理混合：

```
mix(sourceColor, blurColor, mixAmount)

CPU (SkSL): eval() 返回预乘 RGBA
    sourceColor = (Rs·As, Gs·As, Bs·As, As)  ← 预乘
    blurColor   = (Rb·Ab, Gb·Ab, Bb·Ab, Ab)  ← 预乘
    result = mix(sourceColor, blurColor, t)   → 预乘结果

GPU (GLSL): texture() 返回直通 RGBA → fix 后预乘
    sourceColor = texture() → (Rs, Gs, Bs, As) → .rgb *= .a → (Rs·As, Gs·As, Bs·As, As)
    blurColor   = 同上
    result = mix pre-multiplied colors → 应与 CPU 一致

差异来源: fix_premultiplied_alpha 的 regex 注入 .rgb *= .a
        可能在某些边缘情况的纹理坐标下有 ±1 的舍入差异
```

3.33% 像素差 1 级（maxΔ=1）在 8-bit 量化误差正常范围内，属于不可避免的精度容差。

### 路径 4：多点采样累积（variable_radius_blur_approx — 6.54%, picture_blur — 14.0%）

```
模糊采样: 13~50 个采样点围绕中心像素

每个采样点坐标:  (cx + R·cos(θ_i), cy + R·sin(θ_i))

CPU cos(θ_i) vs GPU cos(θ_i) 差异 ~6e-7
    → 采样坐标偏移 ~R × 6e-7 ≈ 24 × 6e-7 ≈ 1.4e-5 像素/点

13 个采样点 × 1.4e-5 像素/点 ≈ 2e-4 像素总偏移
    → 加权平均中每个点权重微调
    → 最终颜色差异 maxΔ=20 (低强度, 分布广泛)
```

**picture_blur 有 14% 像素受影响, 但 maxΔ 仅 9**：
更多采样点 (50+) × 更长的采样半径 → 分布更广但每像素差异更小。

## 验证方法

所有测试均通过 `tests/runner.sh fulltest` 执行，对比三种模式：
- **v1 report**: 原始代码渲染 vs 转换后代码渲染（跨语言 + 跨后端）
- **v2 report**: v1 转换结果 vs 逆向转换结果（跨后端）
- **roundtrip report**: v1 原始 vs v2 逆向（同后端闭环验证）

roundtrip PSNR=∞ 证明转换链路语义无损。v1/v2 的差异全部来自上述渲染后端差异，可通过 `--gpu` 标志消除。

## 案例 5：water_ripple 纹理硬边界处的「抗锯齿」错觉

### 现象

water_ripple 的 v1 对比报告中，底部中间偏左侧（x≈424-435, y≈300-710）的深蓝与橙红条纹交界处，CPU 渲染显示硬边缘（纯蓝或纯橙），GPU 渲染显示平滑渐变（混合棕色）。

### 被测数据

从 `sksltoglsl/test1/water_ripple/v1/` 渲染结果中提取：

| 像素 | CPU (before) | GPU (after) |
|------|-------------|-------------|
| (424, 615) | (33, 87, 123) 纯深蓝 | (127, 100, 88) 棕灰混合 |
| (425, 608) | (220, 113, 54) 纯橙 | (126, 100, 88) 棕灰混合 |
| (425, 399) | (220, 113, 54) 纯橙 | (126, 100, 88) 棕灰混合 |

显著特征：相邻像素在 CPU 上分别是**纯蓝**和**纯橙**（硬边缘），而 GPU 上都是**棕灰中间色**（平滑过渡）。棕灰 = (蓝+橙)/2：

```
(33+220)/2=127, (87+113)/2=100, (123+54)/2=89
```

### 根因：input.png 的 1 像素硬边界

`input.png`（`make_demo_image()` 生成）的条纹图案在 x=425 和 x=426 之间有 1 像素宽的硬过渡：

```
x=425: (33, 87, 123, 255) ← 深蓝背景条纹
x=426: (220, 113, 54, 255) ← 橙色条纹
```

源图像本身没有渐变——边界两侧是纯色。任何「渐变」效果完全来自采样时的双线性插值。

### 计算追踪

以像素 (424.5, 615.5) 为例，追踪 water_ripple 的 `distortedCoord` 计算：

**参数**：
- `iResolution = (1280, 720)`，`progress = 0.35`，`waveCount = 2.0`
- `rippleCenter = (0.5, 0.7)`，`timeValue = 0.245`

**计算链**（fp64 精度）：

```
uvHomogeneous = (424.5/720, 615.5/720) = (0.5896, 0.8549)
waveCenter = (0.5×1280/720, 0.7) = (0.8889, 0.7000)
waveVector = (-0.2993, 0.1549)
propagatedDistance = √(0.2993² + 0.1549²) = 0.3370
distanceToWave = 0.3370 - 2×0.245 = -0.1530

calcWave(d) = -sin(31d) × smoothstep(-0.6,-0.3,d) × smoothstep(0,-0.3,d)

有限差分梯度 = (calcWave(-0.152) - calcWave(-0.154)) / 0.002 = 4.502

intensity = 4.502 × 0.1932 × 0.8425 × 0.012 = 0.008795

normWV = (-0.8882, 0.4595)
circles = (-0.8882×0.008795, 0.4595×0.008795) = (-0.00781, 0.00404)

distortedCoord X = (0.3316 - 0.15×(-0.00781)) × 1280 = 426.00
```

**关键结果**：`distortedCoord X = 426.00`——恰好落在 x=425（蓝）和 x=426（橙）的**像素边界上**。

### 差异机制

```
                     x=425          x=426
                      │               │
     input.png:   纯蓝色 (33,87,123)  │  纯橙色 (220,113,54)
                      │     边界      │
                      │← 0.5px →│← 0.5px →│
                      │               │
    GPU distortedCoord:        426.00 ─┐
    CPU distortedCoord:        425.99 ─┘  (≈0.01px 偏移)
                                │         │
    GPU 采样: 在边界上 → 双线性插值 → (蓝+橙)/2 = 棕灰混合
    CPU 采样: 在蓝色侧 → 无双线性   → 纯蓝
```

**偏移量级分析**：

Skia RuntimeEffect 内部使用 fp32 算术。从 `propagatedDistance` 到 `distortedCoord` 的计算链中，每一步的 fp32 截断累积约 `1e-6` 的相对误差。在 1280 像素宽的画面中，这转化为约 `0.001` 像素的绝对坐标偏移。

但 GPU GLSL 的 `sin()` 使用 fp32 π 做参数约简，而 CPU libm 的 `sin()` 使用高精度 π。这个差异单独贡献约 `6e-7` 的 `sin` 输出偏差，经过 ×500 有限差分放大后，梯度偏差约 `3e-4`，最终坐标偏移约 `0.006` 像素。

虽然 0.006 像素的偏移微乎其微，但当采样坐标本身恰好落在硬边界上时，即使是亚像素级的偏移也足以改变双线性插值的行为——从「两色混合」变为「单色返回」。

### 结论

> 观察到的「CPU 无抗锯齿 / GPU 有抗锯齿」**不是**渲染引擎的能力差异。
> 
> 它是 input.png 的 1 像素硬边界与 water_ripple 的 `distortedCoord` 恰好落在该边界上的**巧合叠加**：
> 
> - CPU 的 sin→有限差分→坐标链使采样点偏向蓝色侧 → 返回纯色 → **看起来像硬边缘**
> - GPU 的 sin→有限差分→坐标链使采样点留在边界上 → 双线性插值 → **看起来像渐变**
> 
> 如果 input.png 的条纹边界有平滑过渡（如 3-5 像素的渐变带），这一观感差异将完全消失。
